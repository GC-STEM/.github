# Contributing

Thank you for helping improve GC-STEM repository materials.
You can report an error, describe confusing instructions, identify
an accessibility barrier, or suggest an improvement.

You do not need Git expertise to provide useful feedback.

## Start with the Affected Repository

Use the Issues tab in the repository containing the material you
want to improve. An Issue is a report that helps maintainers track
a problem or suggestion.

Check for an existing report when practical. If you find one, add
useful information rather than opening a duplicate.

If Issues are unavailable, you cannot use GitHub, or you prefer a
private channel, contact your instructor using the method listed
in Brightspace.

For assignment help, grading questions, or other support needs,
see [Support](https://github.com/GC-STEM/.github/blob/main/SUPPORT.md).

## Report a Problem or Suggest an Improvement

Include what you know:

- Where you found the problem: a file, heading, step, or link
- What happened or what was unclear
- What you expected, if you know
- How the problem affects your work
- Your suggested improvement, if you have one

Relevant error messages or a small example may help. You do not
need to diagnose the cause, propose a solution, or provide every
technical detail before submitting a report.

If the problem blocks required coursework, also contact your
instructor. Repository reports do not change assignment requirements
or deadlines.

## Protect Coursework and Private Information

Before posting:

- Remove passwords, authentication codes, access tokens, and keys.
- Remove student records, grades, private feedback, personal contact
  information, and private communications.
- Share only the assignment context or code needed to explain the
  problem, consistent with course instructions.
- Do not post completed solutions, answer keys, or restricted
  assessment materials.
- Cite sources for material you did not create.
- Follow course rules for collaboration and AI assistance.

Report suspected vulnerabilities or exposed information through
[private security reporting](https://github.com/GC-STEM/.github/blob/main/SECURITY.md).
Report conduct concerns through
[private conduct reporting](https://github.com/GC-STEM/.github/blob/main/CODE_OF_CONDUCT.md).

## Proposing File Changes

Reporting a problem does not require you to edit repository files.

Students should submit a pull request only when course instructions
or a maintainer invite them to do so. A pull request proposes file
changes for review. Follow your course's setup instructions when
creating your own coursework repository.

Faculty, staff, and other authorized contributors should:

1. Confirm the current course requirements and discuss substantial
   changes with the responsible course owner.
2. Follow the repository's branch and review process.
3. Keep the proposed change focused and explain its purpose.
4. Check accuracy, relevant functionality, and accessibility.
5. Update related documentation and identify any required approvals.

Repository review does not replace required academic, accessibility,
privacy, security, legal, or administrative approval.

For reuse permissions, consult the licensing notice in the
repository containing the material and any applicable course
instructions. Public availability alone does not establish
permission to reuse content.

## What Happens Next

Maintainers may request clarification, combine duplicate reports,
accept a suggestion, revise it, postpone it, or explain why it cannot
be adopted.

A report does not guarantee acceptance or establish a response
deadline. Wait for agreement on the scope before beginning a
substantial change.
